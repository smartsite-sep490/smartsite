# Danh mục API mobile đang sử dụng

Cập nhật 21/11/2026: tab **Đơn đã gửi** của Worker dùng `myWorkerRequests` → `GET /sites/{siteId}/my-requests` (R), tổng hợp đơn nghỉ, tăng ca, thay đổi/đổi ca và sửa công của chính tài khoản. API trả `leaveAvailableAt` và `serverTime` cho khóa gửi đơn nghỉ 24 giờ; có bộ lọc loại/trạng thái/ID và phân trang. `attendanceTimeRequests` thêm bộ lọc `requestId` để mở chính xác đơn từ thông báo, kể cả ngoài trang/hàng chờ hiện tại. Xem [quy tắc và kiểm chứng](worker-leave.md). Các số liệu kiểm kê bên dưới giữ mốc 20/11, trước thay đổi này.

Đối chiếu mã nguồn và Swagger local ngày **20/11/2026** sau bổ sung mobile. Có **101 hàm client**, **142 vị trí gọi**, tương ứng **102 cặp HTTP method + URL** trong 75 tệp thuộc đồ thị import từ entry app. Tất cả thao tác có controller tương ứng và có trong Swagger của backend đang chạy. Đây là xác nhận kết nối ở mức mã/route, không phải xác nhận đã thử thành công toàn bộ payload/quyền/dữ liệu thực.

Mọi URL dưới đây có tiền tố **`/api/v1`**. C = tạo, R = đọc, U = cập nhật, D = xóa/thu hồi/lưu trữ. POST có thể là lệnh kiểm tra, không mặc định là C. Tham số `{id}` là ID của tài nguyên nêu ở dòng đó; không dùng lẫn `workerId`, `scheduleId`, `dayId`, `documentId`. Query filter như khoảng ngày, trạng thái, paging, `dayId`, `contractorId` vẫn phải truyền theo màn gọi.

Đọc [bản giải thích luồng và phần còn thiếu](mobile-api-audit.vi.md) trước nếu bạn muốn biết phải thực hiện bước nào để dữ liệu xuất hiện.

## Các thao tác không cần HTTP API

Chuyển tab, chọn tuần/ngày/tháng, mở/đóng modal, lọc dữ liệu đã tải, chọn ảnh/tệp từ máy, bỏ tệp chưa nộp, đổi ngôn ngữ (lưu SecureStore), tạo ảnh QR từ token server và chia sẻ tệp đã tải là xử lý tại thiết bị. Chúng không phải API CRUD còn thiếu. Quên mật khẩu đã dùng các API mã email/đặt lại ở mục A. Push native được chuẩn bị cho bản build riêng về sau; hiện người dùng chưa yêu cầu build app.
