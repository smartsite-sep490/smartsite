# C04 tracked-frame storage prototype

This source is unregistered. It does not enable v1.5 HTTP intake, a migration at startup, camera/model processing, or notification delivery. It depends on the canonical tracked-frame contract candidate in PR #133; that candidate is not yet immutable Main provenance for the AI repository.

The prototype adds one technical `ai_subject_segment` table and nullable typed fields to existing raw event storage. It preserves original event bytes, hashes, receipts, decimal uint64 sequences and original PERSON positions. Pending raw receipts do not imply a sealed frame or a business episode.

Raw staging authenticates each original receipt and retry. Server-injected limits bound pending frames, parts, payload bytes and original deadlines. Explicit bounded recovery expires orphan/predecessor work without inventing part zero or requiring an AI retry. It never changes sealed outcomes.

The server profile explicitly supplies a route epoch. Every tracked raw row is inserted as `EPISODE_TRACKED` with that immutable epoch; retry, admission and trusted transition recheck it. The existing generation table holds two SQL-owned technical columns (`observation_route_mode`, `tracking_route_epoch`) and an immutable composite owner key/FK. This adds no table or business permission. First raw storage claims the generation transactionally; legacy and tracked families cannot share one generation, and changing a tracked epoch requires a newly issued generation. Existing legacy history is never reclassified. Writing the existing generation row protects stale REPEATABLE READ snapshots as well as READ COMMITTED, instead of relying on a camera lock plus a stale raw-row scan. Resolving/changing an untracked row's camera/session also checks ownership. Historical unresolved rows stay unresolved when rebinding is denied. Runtime rollback preserves this ownership/history; it must not replay tracked rows through legacy delivery.

Technical admission checks source ordering, exact predecessor/head, scope, capture gap/rewind, forks and permanent retirement. Empty capture alone retires nobody. Explicit qualified orphan retirement creates a tombstone without a fabricated PERSON. Original raw nanoseconds govern chronology; SQL copies the original persisted capture timestamp for head references.

The required projection port runs in the same transaction as provisional seal and technical head writes. Failure rolls everything back; it is not a production business projector. Healthy/empty PostgreSQL fixtures use an explicit synthetic port. A new generation/scope stays pending until a trusted transition fence classifies old work and retires old heads.

`TrackedScopeTransition` is an unregistered Backend-control prototype for that fence. It reauthenticates a stored original coordinator against the currently issued LIVE generation/bundle/profile, checks the exact expected old scopes and explicit row bounds, and uses the same camera lock as staging/admission/expiry. It terminalizes old pending work and permanently retires old active heads atomically. Sealed coordinators and their original nonzero members stay unchanged. Original raw/context/receipt/deadline/head history stays intact. Retirement provenance names the server command and authenticated target; it does not fabricate a captured EXIT or an empty frame. A command ID is correlation only, not a durable command receipt; repeated application is state-idempotent. No worker-token endpoint or automatic call to this class is installed.

The same unregistered candidate migration adds an immutable `EVENT_LOCAL`/`TRACKED` discriminator and segment/scope reference to the existing `safety_episode` table. Existing episodes default to EVENT_LOCAL with null tracking fields. TRACKED anchors require an original sealed PERSON claim and a composite segment/scope/Site/camera FK. One segment can have only one episode; the original event/PERSON unique key remains. Tracked raw cannot enter the EVENT_LOCAL path, subject kinds cannot be rewritten, and tracked episode history cannot be deleted. This is storage support only; no healthy episode is created by technical admission and no business projector is installed. The entity columns require this migration: do not deploy this candidate entity against a database where it has not been explicitly applied. The migration remains outside the runtime registry.

`TrackedPpeEpisodeProjection` is an unregistered prototype of the admission transaction's business port. It reconstructs the original issued region/PPE policy, groups qualified PPE findings by technical segment and subtype/Zone, and retains original per-part event/PERSON mappings. Numeric tracker labels may change without rewriting the first finding's legacy grouping-key bytes. Healthy people acquire technical heads without empty safety episodes. Repeated findings advance observation counts/history without unread/content revision increments; a new subtype or changed region set advances the episode revision once per subject batch. Original timestamps are copied from raw storage. This port does not emit notifications and is not an independently authenticated API: its caller must perform original-part authentication and transactional sealing/head admission first.

Explicit captured retirement and the trusted scope fence seal collection for existing TRACKED episodes of the retired segments in the same transaction. Empty capture alone does not seal collection. This preserves the last actual PERSON observation, finding/review status, content/seen revisions and recipients: technical collection ending is not a safety resolution or a fabricated Zone EXIT. The scope fence uses the same business helper and scoped segment/Site/camera join; no empty episode is created for a healthy retired segment.

`TrackedEpisodeFrameQuery` is an unregistered internal reader of original per-finding observation mappings, not a replacement of the existing MF08 readers or public episode DTO. It pages original event/PERSON/PPE indexes with a decimal uint64 upper-sequence fence and a maximum of 20 mappings per page. It validates original canonical payload/hash/receipt binding, admitted coordinator/scope and issued PPE policy for each finding. It never uses the episode anchor image or identity for later findings. FRAME reads and mechanical PERSON crops reuse the existing bounded JPEG/SHA/dimension reader and expose no storage URI. Real current account/session and existing Admin/Site Safety Officer roles, mapping and provenance are checked before and again after file I/O. Mechanical crops are not Worker identity; no identity decision or permission is inferred. Public contracts, controller/client/UI integration and R2 support remain separate work.

## Verification scope

### Material-only inbox composition

Inbox summaries discriminate original EVENT_LOCAL event/PERSON references from TRACKED segment/scope references. `SafetyEpisodeInboxSummary` widens the inbox only; legacy detail and per-observation identity types stay separate. The reader projects optional candidate metadata from the episode row JSON, so schemas without candidate columns still serve EVENT_LOCAL records. A present invalid discriminator/segment/hash fails closed rather than falling back to the anchor event. The migration remains unregistered; this compatibility change does not activate tracked intake or delivery.

The unregistered `TrackedPpeInboxProjection` composes the existing tracked PPE business port and existing `safety_episode_recipient` table inside the admission owner's transaction. Only material batches project recipients. Eligibility stays active, non-forced-password Site Safety Officer; selected account/role rows are locked through commit. Admin, Site Manager, another Site and disabled/forced-password users are not fallback recipients. A caller-supplied bounded fanout policy rejects overflow atomically rather than truncating delivery; prototype limits are not qualified capacity.

New recipients start at seen revision zero. Existing seen revision and first-delivered timestamp are preserved; a new content revision becomes unread naturally. Repeated frames do not update recipient timestamps, reset reads or backfill new role assignments. Backfill/escalation is a separate policy. Missing eligible recipients returns an explicit gap outcome; this is not all-clear or an external delivery acknowledgement. No legacy `user_notification` is written, and `deliveryAdmitted` remains false. Current-scope inbox reads still hide revoked recipients while retaining their historical rows.

`tracked-ppe-inbox.integration.test.ts` exercises real isolated PostgreSQL admission/projection: two PPE findings share one episode, eligible versus ineligible users, no repeat backfill, material revision/read preservation, ten exact retries, cap rejection, recipient failure rollback and explicit missing recipients. It uses synthetic users/observations, not live notifications. Human review/representative-evidence material hooks, public inbox DTO integration, notification routing and runtime activation remain open.

### Storage and admission tests

Meaningful tests are in `tracked-frame-parts.test.ts`, `tracked-head-plan.test.ts`, `tracked-storage-migration.test.ts`, and the four `integration/*tracked*` / subject-storage fixtures. They cover immutable retries, reverse parts, scoped bounds, deadline concurrency, predecessor recovery, original nonzero PERSON, atomic rollback, tombstones and capture rewind. Integration tests use the dedicated isolated test DataSource; never point them at website/demo or production databases.

The migration remains absent from the runtime registry. Reversal refuses tracked history. No existing raw history is backfilled as TRACKED.

- Qualified tracker/profile, measured clock/gap/capacity policies, query plans and operational performance.

`FIRST_COMMITTED_CAPTURE` and numeric policies are explicitly injected prototype choices, not qualification of unseen earlier frames. Coarse legacy raw processing status plus `TRACKED_RAW_STORED_NO_PROJECTION` must not be interpreted as business admission. Only the scoped typed state and committed transaction describe this prototype's technical outcome.
